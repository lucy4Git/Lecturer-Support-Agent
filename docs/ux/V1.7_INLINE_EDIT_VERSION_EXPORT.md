# v1.7 Inline Editing, Versions and Export UX

## One work area

A generated lesson plan, rubric, test or report remains inside the same conversation. The user does not open a separate artifact application.

## Inline controls

Where authorised, an output card provides:

- **Edit** — opens an inline editor and creates a new immutable version on save.
- **History** — lists versions, creator and change reason.
- **Restore** — copies an older version into a new current version.
- **Submit for review** — changes lifecycle from draft/changes requested to under review.
- **Approve / release** — visible only to roles with the relevant academic permission.
- **Export** — creates Markdown, HTML, Word, PDF, PowerPoint, Excel or a controlled student copy.

## Module context

A module selector is displayed in the conversation header/composer for users with authorised module offerings. The selected context travels with the message and is shown on the resulting output. Users can still choose generic assistance when no module context is needed.

## Safety communication

Risk, review and release state are visible as badges and plain-language notices. The UI must never imply that AI generation equals academic approval. Unsafe or unavailable actions are hidden or disabled and also enforced by the API.

## Responsive behaviour

On smaller screens, controls wrap into accessible groups and the module selector remains usable without obscuring the message composer. Full keyboard navigation, focus states, accessible labels and browser validation remain mandatory acceptance work on the owner machine.

# v2.2 Insights, Reports, Audit Centre and Settings UX

## Interaction principle

The Lecturer Support Agent remains one commercial AI application. v2.2 adds operational views to the existing shell; it does not create a second analytics product, administration portal or artifact workspace.

## Navigation by active role

### Institution Administrator

- Insights
- Reports
- Audit centre
- Platform settings

### Head of Department

- Insights scoped to authorised departments
- Reports scoped to authorised departments

### Module and Programme Coordinators

- Insights and reports for authorised academic scope

### Lecturer and Internal Moderator

- Personal insights and permitted reports

### External Moderator and External Reviewer

- Personal insight view only; no institutional reports, Audit Centre or settings

## Insights view

The view presents concise cards and operational summaries for:

- AI conversations;
- teaching outputs;
- materials added;
- open insight alerts;
- output mix;
- provider mix;
- teaching delivery;
- readiness;
- moderation;
- workload.

Every view clearly displays its scope and period. Empty and pending-runtime states are explicit rather than filled with invented data.

## Reports view

Users see authorised report definitions, completed report runs, format, status, creation time and checksum. Creating a report does not alter source records. A run captures an immutable data snapshot for later verification.

## Audit Centre

The Audit Centre supports filtered institutional audit review and export. It is visible only to the Institution Administrator. The interface must not expose password hashes, API keys, document contents outside scope, or raw provider errors.

## Platform settings

The settings view groups non-secret institution configuration by category. It shows version, scope, lock state and last update. Credential fields never display a real key; secret-backed integrations show only a reference or configured/not-configured state.

## Responsive and accessible behaviour

- All panels remain inside the same desktop, tablet and mobile shell.
- Navigation collapses to the existing mobile drawer.
- Cards reflow without horizontal scrolling at common viewport widths.
- Tables use responsive card fallback where necessary.
- Status is conveyed by text as well as visual styling.
- Buttons, filters and fields retain accessible labels and keyboard focus.
- Loading, empty, error and retry states are required.

## Validation note

Source code and static tests are complete. Live preview, browser screenshots, keyboard testing, screen-reader review and responsive validation remain owner-machine validation tasks.

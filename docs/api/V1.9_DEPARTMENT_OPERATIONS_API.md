# v1.9 Departmental Teaching Operations API

Base path: `/api/v1/department-operations`

## Academic calendar
- `POST /calendar/events`
- `GET /calendar/events`

## Teaching plans and delivery
- `POST /teaching-plans`
- `GET /teaching-plans`
- `POST /teaching-plans/{plan_id}/versions`
- `POST /teaching-plans/{plan_id}/sessions`
- `POST /teaching-sessions/{session_id}/status`

## Module readiness
- `POST /readiness/profiles`
- `POST /readiness/profiles/{profile_id}/items`
- `PATCH /readiness/items/{item_id}`
- `POST /readiness/profiles/{profile_id}/evaluate`

## Workload
- `POST /workloads/activities`
- `GET /workloads/{user_id}?academic_period_id=...`

## Lecturer handover
- `POST /handovers`
- `GET /handovers`
- `POST /handovers/{package_id}/versions`
- `POST /handovers/{package_id}/transition`

## Department dashboard
- `GET /dashboards/departments/{organisational_unit_id}`

All endpoints require the active role selected at login, tenant context, and an appropriate organisational scope. Runtime database row-level security provides an additional enforcement layer.

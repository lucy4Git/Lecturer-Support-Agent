# v1.5 Unified AI Conversation API

All endpoints require an authenticated active-role session and the `ai.use` permission.

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/api/v1/conversations` | Create a new unified teaching conversation. |
| `GET` | `/api/v1/conversations` | List the current user's active conversations. |
| `GET` | `/api/v1/conversations/providers` | Return non-secret provider configuration status. |
| `GET` | `/api/v1/conversations/{conversation_id}` | Open a conversation and its ordered messages. |
| `DELETE` | `/api/v1/conversations/{conversation_id}` | Archive the user's conversation without deleting history. |
| `POST` | `/api/v1/conversations/{conversation_id}/messages` | Classify, route, generate, verify, persist, and return one inline response. |

## Message request

```json
{
  "content": "Generate a 2-hour practical lesson on IoT sensors for diploma students.",
  "attachment_version_ids": [],
  "institutional_context": null
}
```

## Response contract

The response contains:

- persisted conversation, user message, and assistant message;
- explainable task classification;
- inline output type, title, Markdown, and review status;
- source cards derived only from actual retrievals;
- citation-integrity warnings;
- selected provider and model;
- every attempted provider and fallback result.

## Security and privacy

- Conversation ownership is checked in addition to tenant RLS.
- The active role must have `ai.use`.
- Provider API keys are read only from secret environment settings.
- Restricted assessments can be forced to Ollama-only routing.
- Provider requests include internal identifiers only in local metadata; adapters do not send unnecessary personal profile information.
- OpenAI requests set `store=false` in the adapter.
- Archived conversations remain auditable and are not destructively deleted.

## Error behaviour

- `401`: inactive or invalid session.
- `403`: active role lacks `ai.use`.
- `404`: conversation is outside the current user's authorised ownership/tenant scope.
- `422`: invalid message content or attachment identifiers.
- `503` should be returned by the production exception mapping when every permitted provider fails. The development mock prevents false success claims while allowing local UI pipeline testing outside production.

# v1.7 Teaching-Output API

All routes are under `/api/v1` and require a valid tenant, user, membership and active-role session.

## Module context

`GET /teaching-contexts` lists module offerings authorised for the active role. Lecturers are restricted to active lecturer assignments; broader roles are still constrained by organisational scope.

A conversation message may provide `module_offering_id`. The service resolves the offering, module, academic period, outcomes and programmes and stores an immutable `academic.module_context_snapshots` record for the AI request.

## Inline output routes

- `GET /teaching-outputs/{output_id}` — current output, lifecycle, current version and safety status.
- `GET /teaching-outputs/{output_id}/versions` — immutable version history.
- `POST /teaching-outputs/{output_id}/versions` — create a manual edit version.
- `POST /teaching-outputs/{output_id}/versions/{source_version_id}/restore` — restore content by creating a new version.
- `GET /teaching-outputs/{output_id}/workflow` — lifecycle history.
- `POST /teaching-outputs/{output_id}/workflow` — submit, request changes, approve, release or archive.
- `POST /teaching-outputs/{output_id}/exports` — render a selected/current version.
- `GET /teaching-outputs/exports/{export_id}/download` — re-authorised export download.

The static export-download route is declared before the dynamic output route to prevent path capture.

## Permissions

- `outputs.edit` — create or restore versions.
- `outputs.review` — review and request changes.
- `outputs.approve` — formally approve authorised outputs.
- `outputs.release` — release approved content.

Institution Administrator and Head of Department remain independent. Institution administration does not imply academic approval.

## Export contract

Supported formats: `markdown`, `html`, `docx`, `pdf`, `pptx`, `xlsx`.

Audiences include generic/lecturer packs and student copies. A student-copy request is denied unless lifecycle and assessment-safety rules permit it. Generated files are placed in object storage and represented by `content.export_jobs` plus a `content.storage_objects` record.

## Failure behaviour

The API fails closed for unauthorised module context, disallowed assessment generation, invalid workflow transitions, unsafe student release, missing versions and inaccessible exports. Error payloads must not expose provider credentials, object-storage keys or another tenant's identifiers.

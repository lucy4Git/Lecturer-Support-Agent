# v2.2 Analytics, Reporting and Governance API

All endpoints are under the configured `/api/v1` prefix and require an authenticated tenant, user, membership and active role assignment.

## Analytics

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/analytics/overview` | Return role-scoped teaching and operational insight cards for a bounded period. |
| GET | `/analytics/ai-usage` | Return the current-month request, token, cost and latency ledger within authorised scope. |
| GET | `/analytics/report-definitions` | List active shared or owned report definitions. |
| POST | `/analytics/report-definitions` | Create a report definition when `reports.manage` is authorised. |
| GET | `/analytics/report-runs` | List report runs visible to the requesting user. |
| POST | `/analytics/report-runs` | Generate and persist a checksum-protected report snapshot. |
| GET | `/analytics/alerts` | List open, acknowledged or resolved insight alerts within scope. |
| POST | `/analytics/alerts/{alert_id}/action` | Acknowledge, resolve or reopen an authorised alert. |

Supported overview periods are 1–366 days. Personal roles are forced to personal scope even when a broader scope is requested.

## AI usage governance

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/ai-governance/policies` | Read active policies permitted by the current role. |
| POST | `/ai-governance/policies` | Create a scoped policy when `ai_governance.manage` is authorised. |

A policy may define:

- allowed and denied providers;
- local-only privacy classes;
- tasks that require source retrieval;
- monthly request and token limits;
- monthly estimated-cost limits and currency;
- warning thresholds;
- hard-limit enforcement.

The conversation engine evaluates the effective policy before provider selection. A hard-blocked request receives a safe policy error; provider secrets are never returned.

## Audit Centre

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/audit-centre/events` | Search tenant audit events by date, actor, action or resource. |
| GET | `/audit-centre/security-events` | Review tenant security events and resolution status. |
| POST | `/audit-centre/exports` | Create a JSON or CSV audit export with record count and SHA-256 digest. |

Audit Centre access is restricted to Institution Administrators through `audit.centre.read` and `audit.export` permissions.

## Platform settings

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/platform-settings` | List authorised versioned settings, optionally by category. |
| PUT | `/platform-settings/{category}/{setting_key}` | Create or update a setting while retaining a version number and audit trail. |

The API rejects raw credentials, passwords, API tokens and private keys. Secret-backed configuration accepts only references such as:

```json
{
  "scope_type": "institution",
  "value_type": "secret_reference",
  "value": {"environment_variable": "OPENAI_API_KEY"}
}
```

## Report integrity

Each successful report run records the scope, period, requester, output format, immutable result payload and SHA-256 digest. JSON, CSV and PDF are represented as governed format contracts; actual live rendering and object-storage delivery remain part of owner-machine validation.

## Failure behaviour

The API fails closed for unauthorised scope, unsupported roles, invalid periods, invalid provider names, raw secret values, inaccessible alerts, and prohibited audit/settings actions. Provider policy failures return safe messages without exposing provider payloads or credentials.

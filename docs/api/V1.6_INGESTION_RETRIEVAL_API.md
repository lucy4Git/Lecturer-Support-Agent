# v1.6 ingestion and retrieval API

- `POST /api/v1/documents/upload` — upload one version and process it.
- `GET /api/v1/documents/{document_id}/versions` — authorised immutable history.
- `PATCH /api/v1/documents/versions/{version_id}/status` — controlled lifecycle transition with append-only audit evidence.
- `POST /api/v1/documents/versions/{version_id}/process` — process or reprocess one version.
- `GET /api/v1/documents/versions/{version_id}/processing` — extraction, chunks, indexing and job status.
- `POST /api/v1/bulk-uploads` — contextual multi-file or safe ZIP upload, immutable versioning, optional processing.
- `GET /api/v1/bulk-uploads/{batch_id}` — batch and item status.
- `POST /api/v1/conversations/{conversation_id}/messages` — accepts authorised `attachment_version_ids` and performs source-aware retrieval inside the same work area.

All upload and retrieval operations are constrained by active role, tenant, and scope. API keys are not accepted in payloads.

## Lifecycle controls

A status change never deletes or rewrites earlier versions. Review-stage transitions require `content.version.review`; approval, publication and supersession require `content.version.approve`. Invalid jumps, such as `working` directly to `published`, fail closed.

# v2.4 Automation and Operations API

All routes are tenant scoped and require the independent Institution Administrator role plus the corresponding permission.

## Schedules

- `GET /api/v1/operations/schedules`
- `POST /api/v1/operations/schedules`
- `PATCH /api/v1/operations/schedules/{schedule_id}`

Only governed interval schedules are accepted in v2.4. Minimum interval: 60 seconds. A schedule may target only an allow-listed background job type.

## Notification delivery evidence

- `GET /api/v1/operations/notification-deliveries`

The API exposes delivery state and safe error codes, never provider credentials or private message bodies.

## Retention

- `GET /api/v1/operations/retention-runs`
- `POST /api/v1/operations/retention-runs`

`dry_run=true` creates an evidence-only preview. `dry_run=false` applies only allow-listed reversible archive or expiry actions. Hard deletion is unsupported.

## Existing job operations

The existing job, dead-letter, backup and restore-drill endpoints remain available. v2.4 adds real handlers for notifications, outbox, external-access expiry, retention, reports, audit exports, ingestion and output exports.

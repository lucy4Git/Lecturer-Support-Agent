# v1.7 Teaching-Output Production

## Generic intelligence with optional context

The Lecturer Support Agent remains generic by default. Selecting a module adds authorised context; it does not turn the product into a retrieval-only system. The prompt clearly separates general model knowledge, authorised module context, uploaded institutional evidence and verified external sources.

## Production pipeline

1. Authorise active role and tenant.
2. Classify the lecturer-support task.
3. Enforce assessment-generation role gates.
4. Resolve optional module context.
5. Store an immutable context snapshot.
6. Build the provider-neutral prompt and output blueprint.
7. Route to an approved provider/model.
8. Parse the response into structured sections.
9. Persist message, generated output and version 1.
10. Evaluate assessment safety.
11. Create lifecycle and workflow evidence.
12. Render inline controls according to permission and state.

## Output blueprints

Blueprints define expected sections and quality gates for lesson plans, practicals, assessments, rubrics, marking guides, case studies, tutorials, moderation/alignment reports and departmental analyses. A missing section creates a warning; it is not silently invented after generation.

## Human authority

All quizzes, tests, assignments, examinations, rubrics and marking guides require human review. The model may prepare a draft but may not claim approval, moderation or institutional compliance. Formal state changes are attributed to an authorised user and active role.

## Provider neutrality

The production workflow is independent of OpenAI, Claude, Gemini, DeepSeek or Ollama. Model-specific responses are normalised into one internal contract, and provider/model provenance remains attached to the output version.

# v1.5 Acceptance Criteria

## Functional

- [x] One conversation endpoint accepts all lecturer-support requests.
- [x] The platform chooses an output type without exposing an agent or model picker.
- [x] Generic responses do not require uploaded institutional content.
- [x] Lesson, practical, assessment, rubric, marking, case, moderation, alignment, and departmental intents are classified.
- [x] OpenAI, Claude, Gemini, DeepSeek, and Ollama adapters implement a common contract.
- [x] Provider fallback attempts are recorded.
- [x] Restricted requests can be limited to a local provider.
- [x] Source discovery is optional and request-sensitive.
- [x] Unknown source markers, URLs, and DOIs are removed.
- [x] Outputs and sources appear inline in the unified UI.
- [x] Conversation and output records are persisted through the existing schema.

## Security and governance

- [x] Active role requires `ai.use`.
- [x] Conversation owner and tenant are checked.
- [x] Provider secrets are not returned by the provider-status endpoint.
- [x] Formal approval is never inferred from AI generation.
- [x] High-stakes outputs require human review.
- [x] Development mock is excluded from production configuration.

## Static validation

- [x] Python compilation passes.
- [x] 30 unit tests pass.
- [x] TypeScript/TSX syntax passes.
- [x] FastAPI conversation routes load.
- [x] No real `.env` or API keys are packaged.

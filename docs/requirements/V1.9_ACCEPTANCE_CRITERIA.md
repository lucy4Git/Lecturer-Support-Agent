# v1.9 Acceptance Criteria

v1.9 is accepted only when:

1. A lecturer can create and version a teaching plan for an assigned module offering.
2. A delivered session preserves planned and actual times and cannot be returned to planned status.
3. Readiness scoring excludes not-applicable items and blocks readiness when a blocking requirement is incomplete.
4. A Head of Department can review scoped readiness and workload without receiving Institution Administrator permissions.
5. Workload weighting and configured limits produce a reproducible overload result.
6. Calendar events cannot end before they start and remain scoped to the authorised institution or academic unit.
7. Handover edits create immutable versions; invalid lifecycle transitions fail closed.
8. An incoming lecturer or authorised academic manager can accept an assigned handover.
9. The departmental dashboard identifies missing teaching plans, readiness risk, overload, and overdue handovers.
10. Every tenant-owned v1.9 table has row-level security applied by migration.
11. All v1.9 unit tests and validators pass.
12. Owner-machine validation proves migrations, scope enforcement, and browser workflows before production claims are made.

# v2.2 Acceptance Criteria

## Functional

- [x] Role-scoped insight overview exists inside the unified workspace.
- [x] Lecturers and reviewers are restricted to personal analytics.
- [x] Heads of Department and coordinators use authorised organisational-unit scope.
- [x] Institution Administrators can request institution-wide analytics.
- [x] Report definitions and immutable report runs are implemented.
- [x] AI provider, privacy, source and monthly-limit policies are implemented.
- [x] Conversation routing consumes the effective policy.
- [x] Daily AI usage ledger recording is implemented.
- [x] Audit-event search, security-event review and checksum exports are implemented.
- [x] Versioned non-secret platform settings are implemented.
- [x] Insights, Reports, Audit centre and Settings remain in the unified application shell.

## Security

- [x] All new records are tenant-owned.
- [x] Analytics schema is included in RLS policy generation.
- [x] Audit Centre and settings management remain Institution Administrator-only.
- [x] Head of Department and Institution Administrator roles remain independent.
- [x] Raw API keys and secret-shaped values are rejected from platform settings.
- [x] Personal analytics are user-scoped.
- [x] Report and audit-export integrity digests are recorded.

## Static quality

- [x] Unit tests cover scope, policies, provider filtering, permissions, secrets, migration and UI integration.
- [x] Python sources compile.
- [x] JSON configuration parses.
- [x] PlantUML sources are structurally validated.
- [x] Documentation, index, manifest and checksums are updated.
- [x] Safe archive excludes `.env`, API keys and runtime evidence.

## Owner-machine acceptance pending

- [ ] Migration upgrades a live v2.1 database to v2.2.
- [ ] RLS denies cross-tenant and over-broad role queries.
- [ ] Seeded roles see only the correct analytics navigation and API data.
- [ ] Real Ollama execution writes an accurate daily usage record.
- [ ] Optional cloud-provider execution respects allow/deny policy.
- [ ] Hard-limit and local-only behaviour pass live tests.
- [ ] Reports and audit exports complete against PostgreSQL.
- [ ] Next.js typecheck and production build pass.
- [ ] Desktop, tablet and mobile live-preview tests pass.
- [ ] Accessibility and performance baselines pass.

The release remains `IMPLEMENTED — STATICALLY VALIDATED — OWNER-MACHINE VALIDATION PENDING` until every mandatory runtime criterion is evidenced.

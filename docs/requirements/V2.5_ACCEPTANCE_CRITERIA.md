# v2.5 Acceptance Criteria

## Account security

- Password-reset tokens are random, hashed at rest, single use, tenant bound and time limited. Queued token-bearing message bodies are encrypted at rest.
- Password reset revokes active sessions.
- TOTP verification follows RFC 6238 and recovery codes are single use.
- MFA secrets are encrypted at rest.
- OIDC uses Authorization Code with PKCE, state and nonce.
- ID tokens are validated against issuer, audience, time claims and the provider JWKS.
- Federated accounts are linked by verified email only when an Institution Administrator explicitly enables it.

## Enterprise integration

- Each connection belongs to one institution and stores only a secret reference.
- Each sync creates an immutable sync-run record.
- External records retain source identifiers, hashes and mapping state.
- Synchronisation is bounded, paginated and idempotent.
- Canonical institutional data is not destructively overwritten by an adapter.

## Privacy and deletion

- Active legal holds block deletion.
- Deletion approval is independent from request creation when second approval is enabled.
- Exact storage versions and document-version vectors are deleted for supported document deletion.
- Audit tombstones remain.
- Unsupported resource types fail closed or remain pending a reviewed adapter.

## Backup and recovery

- Backup files remain outside Git and normal project archives.
- Tenant relational exports use the RLS-constrained worker session and do not expose database credentials.
- Object storage is exported only below the active tenant prefix.
- Qdrant export applies a mandatory tenant filter.
- Every backup file has a SHA-256 manifest entry.
- A restore drill verifies all files and PostgreSQL archive readability.
- Production configuration requires an encryption-at-rest attestation.

## Data preparation and evaluation

- Every real source has provenance, licence, intended use and approval status.
- Retrieval permission does not imply model-training permission.
- Evaluation data is isolated from adaptation data.
- No full copyrighted corpus is bundled without item-level rights approval.
- User feedback is tenant scoped and auditable.

## Commercial readiness

- PWA assets do not cache authenticated API responses or confidential content.
- Legal and SLA documents are templates pending professional review.
- The release clearly distinguishes static validation from live validation.
- Institution Administrator and Head of Department permissions remain independent.

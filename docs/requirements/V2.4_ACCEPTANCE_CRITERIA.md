# v2.4 Acceptance Criteria

1. Every allow-listed domain job has a registered handler.
2. Backup and restore drills fail honestly until owner-machine integration is configured.
3. Due interval schedules create idempotent background jobs.
4. The scheduler and worker do not receive PostgreSQL `BYPASSRLS`.
5. In-app notification delivery creates durable evidence.
6. Unsupported channels are marked blocked, not delivered.
7. External access expires automatically after its deadline.
8. Retention defaults to dry-run and never performs implicit hard deletion.
9. Reversible retention actions preserve evidence for every candidate.
10. Report and audit-export jobs store SHA-256 integrity values.
11. Document ingestion and output-export handlers use the authorised immutable version.
12. The Institution Administrator and Head of Department roles remain independent.
13. The operations UI remains inside the unified workspace.
14. No `.env`, API key, model binary or runtime evidence is included in the release archive.
15. Runtime claims remain pending until the owner-machine validation passes.

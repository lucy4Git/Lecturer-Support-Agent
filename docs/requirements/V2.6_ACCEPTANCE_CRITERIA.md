# v2.6 deployment-completion acceptance criteria

v2.6 is source-package complete when all of the following are true:

1. No real `.env`, API credential, private key, password, token, local database, model binary, or unredacted runtime evidence is packaged.
2. Vercel, Render staging, and Render production descriptors are present and parse successfully.
3. Neon migration bootstrap creates the least-privilege `lsa_app`, `lsa_auth`, and `lsa_worker` roles and applies Alembic through `20260803_0012`.
4. Demonstration seeding is disabled by default and refused in production.
5. Staging can create all eight approved synthetic roles using a protected temporary password or invitation process.
6. Public onboarding permits sign-in, SSO, invitation acceptance, and reviewed access requests; no public user can self-assign a privileged role.
7. Hosted embedding adapters support a 768-dimensional governed embedding contract without requiring local Ollama in production.
8. S3-compatible storage supports managed or provider-enforced object versioning.
9. Approved PostgreSQL data, object versions, and Qdrant vectors can be migrated through allowlisted, auditable, checksum-verified procedures.
10. Redis is explicitly treated as clean temporary state and is not migrated.
11. Local and deployed parity manifests compare release, migration, schema, roles, permissions, approved data counts, object checksums, Qdrant configuration, and vector payload fingerprints.
12. GitHub CI includes Python tests, deployment validators, TypeScript checks, Next.js build, secret scanning, CodeQL, dependency review, and container builds.
13. The safe-release tool excludes secrets, caches, local state, runtime evidence, and model binaries.
14. Deployment runbooks explain the exact owner actions required in GitHub, Render, Vercel, Neon, S3, Qdrant, SMTP, and provider dashboards.
15. Staging acceptance validates authentication, all eight roles, uploads, immutable versions, AI generation, sources, moderation, exports, tenant isolation, and parity before production promotion.

Vendor deployment, legal approval, real institutional-data approval, and production acceptance remain owner/institution actions and cannot be embedded as credentials or approvals in a source archive.

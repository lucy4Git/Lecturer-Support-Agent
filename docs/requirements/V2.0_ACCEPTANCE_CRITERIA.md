# v2.0 Acceptance Criteria — Validation Readiness

- **V20-AC-001:** One command can run cumulative static, runtime and live-preview validation.
- **V20-AC-002:** Docker Desktop is never launched automatically.
- **V20-AC-003:** Validation logs are stored outside Git and redacted before retention.
- **V20-AC-004:** The command fails when `.env` is tracked, missing for runtime, or contains template secrets.
- **V20-AC-005:** PostgreSQL, Redis, MinIO, Qdrant, Ollama, API and web have explicit probes.
- **V20-AC-006:** MinIO validation requires bucket versioning to be enabled.
- **V20-AC-007:** Required Ollama generation and embedding models are verified by exact tag.
- **V20-AC-008:** Cloud-provider probes are opt-in and use only a synthetic prompt.
- **V20-AC-009:** Unit, integration, tenant-isolation, typecheck and production-build commands are captured as evidence.
- **V20-AC-010:** Live preview covers Institution Administrator, Head of Department, Lecturer, Internal Moderator and External Reviewer.
- **V20-AC-011:** Live preview runs at desktop, tablet and mobile breakpoints and captures screenshots.
- **V20-AC-012:** Role-independence negative checks are included.
- **V20-AC-013:** A machine-readable JSON summary and human-readable Markdown report are generated.
- **V20-AC-014:** The project remains `validation_pending` unless the full run and live preview pass.
- **V20-AC-015:** Claude is instructed to audit evidence and correct every failure before extending the project.

# v2.3 Production Hardening

## Request controls

Every response receives content-type, frame, referrer, permissions, opener, resource, and content-security headers. Production also receives HSTS. Sensitive authentication, audit, and settings responses are marked `no-store`.

Request `Content-Length` is rejected before application processing when it exceeds the configured maximum. Upload-level limits and safe ZIP inspection remain additional controls.

## Rate limiting

A Redis-backed atomic counter protects authentication and general API requests. Development may fail open to allow local diagnostics; production configuration is rejected unless rate limiting is enabled and fail closed.

## Upload scanning

The `ClamAVMalwareScanner` implements the clamd `INSTREAM` protocol. Raw uploads and expanded ZIP members are scanned before version creation. Production configuration is rejected unless scanning is enabled and fail closed. The disabled scanner reports `disabled`; it never reports that content was scanned.

## Secrets and logs

Structured logs redact values whose keys or contents resemble credentials. The repository continues to contain only environment-variable names. Metrics require a separate token in production. Backup directories and runtime evidence remain ignored and outside safe project archives.

## Remaining proof

Penetration testing, dependency/container scanning, TLS termination, SSO/MFA, live ClamAV signatures, and security-event response remain owner-machine, staging, and pilot validation tasks.

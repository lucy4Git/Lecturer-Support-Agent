# v2.4 Retention and Delivery Safety

## Retention

- Preview is the default.
- Each candidate creates immutable retention-run evidence.
- Only `archive`, `expire`, or `review` are accepted.
- Hard deletion is not implemented.
- Unsupported dispositions are recorded as skipped.
- Tenant row-level security remains active for the worker.
- Retention rules must be active and carry a legal basis where institutional governance requires it.

## Notifications

- In-app delivery is the only built-in channel.
- Email, SMS and webhook requests are recorded as blocked when no approved adapter exists.
- The UI and API never claim an unsupported message was sent.
- Delivery evidence stores safe status and error codes, not API credentials.

## External access

Expiry is enforced from the database time, not the browser. The grant, scheduled expiry event, audit record and recipient notification remain linked and auditable.

# v1.7 Assessment-Safety Controls

## Objectives

Assessment assistance must improve lecturer productivity without exposing confidential answers, student data or unapproved assessment material.

## Role gate

New assessment artefacts may be generated by authorised academic creation roles such as Lecturer, Module Coordinator, Programme Coordinator and Head of Department. Moderators and external reviewers may review assigned material but cannot use review access to create unrelated assessments.

## Deterministic checks

Each assessment-related output version is checked for:

- answer-key or memorandum indicators;
- personal/student identifiers;
- missing or inconsistent mark allocation;
- absence of module context for high-stakes drafts;
- required human review;
- student-copy safety;
- blocked release reasons.

The result is stored in `review.assessment_safety_reviews`; it is not only a transient UI warning.

## Lifecycle rules

A generated assessment starts as a draft. Approval and release are separate actions. Student-facing exports remove answer sections and are denied when personal data or unresolved blockers remain. A released assessment source can still keep a confidential lecturer version and a sanitised student copy as separate export records.

## Non-claims

Passing automated checks does not certify assessment validity, moderation, accreditation or policy compliance. An authorised academic remains accountable for learning-outcome alignment, fairness, difficulty, marks, accessibility, academic integrity and final release.

## Privacy routing

Restricted or unreleased assessments may be governed as local-only or otherwise limited to institution-approved providers. The application must fail closed when the required privacy route is unavailable.

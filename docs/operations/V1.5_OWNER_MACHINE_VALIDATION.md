# v1.5 Owner-Machine Validation

Run this consolidated validation before Claude modifies the project.

## 1. Safe local configuration

```powershell
Copy-Item .env.example .env
.\scripts\security\Initialize-LocalSecrets.ps1
```

Add only the provider keys you intend to test. Keep `.env` ignored.

## 2. Static validation

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\validation\Validate-V1.5.ps1
```

## 3. Infrastructure and database

```powershell
.\scripts\database\Start-DatabaseStack.ps1
.\scripts\database\Initialize-Database.ps1 -InstallDependencies -SeedDemonstrationData
.\scripts\database\Test-TenantIsolation.ps1
```

Docker Desktop must be started manually by the owner; project scripts must not launch it.

## 4. AI providers

```powershell
.\scripts\development\Test-AI-Providers.ps1
ollama list
```

Confirm at least one real provider is available. For restricted-data tests, confirm Ollama is selected when local-only routing is enabled.

## 5. API and web

```powershell
.\scripts\development\Start-API.ps1
.\scripts\development\Start-Web.ps1
```

Validate:

1. Login with each affected internal role.
2. Create and reopen a conversation.
3. Generate a generic answer without institutional material.
4. Generate a practical lesson.
5. Generate a high-stakes assessment and confirm the human-review notice.
6. Request sources and confirm every displayed source opens and exists.
7. Attempt a fabricated marker/URL test and confirm removal/warning.
8. Stop the first provider and confirm permitted fallback.
9. Test a restricted request and confirm local-only routing.
10. Refresh the browser and confirm conversation history persists.

## 6. Live preview evidence

Capture desktop, tablet, and mobile evidence for empty, loading, successful, source-card, warning, failure, and recovery states. Fix every observed issue before reporting v1.5 accepted.

# v1.4 Owner-Machine Validation

Do not run this until the user chooses the consolidated validation checkpoint. Scripts do not start Docker Desktop automatically.

## 1. Preserve the baseline

Verify the downloaded archive hash, extract to a new folder, and commit before testing.

## 2. Create local secrets

```powershell
Copy-Item .env.example .env
.\scripts\security\Initialize-LocalSecrets.ps1
```

Review `.env`. Never upload it.

## 3. Start data services manually

Start Docker Desktop yourself, then:

```powershell
.\scripts\database\Start-DatabaseStack.ps1
.\scripts\database\Initialize-Database.ps1 -InstallDependencies -SeedDemonstrationData
```

## 4. Validate database and isolation

```powershell
python -m alembic current
python -m pytest tests/unit -v
.\scripts\database\Test-TenantIsolation.ps1
```

Confirm:

- migrations reach `20260724_0002`;
- `lsa_app` cannot select password credentials;
- `lsa_auth` cannot bypass RLS;
- demo-north cannot see demo-south;
- Head of Department and Institution Administrator permissions remain independent.

## 5. Start API and web client

In separate PowerShell terminals:

```powershell
.\scripts\development\Start-API.ps1
.\scripts\development\Start-Web.ps1 -InstallDependencies
```

## 6. Demo login

Synthetic users use the temporary demonstration password documented in the seed file and must be forced to change it. Test both institutions and several roles. The demonstration domains are `.example.invalid` and contain no real people.

## 7. Required workflow tests

- Login with one role and confirm another assigned role's permissions are unavailable.
- Refresh token rotates and the previous token fails.
- Logout revokes the refresh session.
- Institution Administrator invites a lecturer and assigns a position label.
- Invitation acceptance creates membership and role scope.
- Institution Administrator creates and moves an organisational unit without cycles.
- Head of Department assigns and reassigns a lecturer; history remains.
- Head of Department views only the authorised department overview.
- Cross-tenant user, role, and organisational access fail.
- Responsive UI works on desktop, tablet, and phone widths.

- database role and RLS verification output;

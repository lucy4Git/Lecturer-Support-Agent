# v2.3 Deployment and Observability

## Deployment assets

- `infrastructure/docker/*.Dockerfile`
- `compose.production.yaml`
- `infrastructure/gateway/Caddyfile`
- `infrastructure/kubernetes/base/`
- `infrastructure/kubernetes/overlays/`
- `infrastructure/observability/prometheus.yml`
- `infrastructure/observability/alerts/lsa.rules.yml`

Production Compose uses required environment substitutions and does not provide real secrets. The API and worker run as non-root users. Kubernetes workloads drop Linux capabilities, prohibit privilege escalation, use resource constraints, and separate web/API/worker processes.

## Signals

The API exposes counters for request totals, status classes, duration totals, and rate-limit rejections. Logs are JSON and include request/correlation context without raw prompts, files, credentials, or provider payloads. `/ready` proves dependency readiness, whereas `/health` proves process liveness only.

## Owner-machine command

```powershell
.\scripts\operations\Test-ProductionConfiguration.ps1 `
  -EnvironmentFile .env.production.local
```

Actual TLS, DNS, image registry, managed secrets, autoscaling, dashboards, alert delivery, and staged rollbacks depend on the selected deployment environment and remain validation tasks.

# v1.7 Owner-Machine Validation

Run this checkpoint before Claude begins the consolidated audit.

## Prerequisites

- Extract the v1.7 SAFE archive outside OneDrive where practical.
- Keep real secrets only in `.env`.
- Docker Desktop may be opened manually; project scripts must not launch it automatically.
- Confirm Ollama and required local models separately.

## Suggested sequence

```powershell
Copy-Item .env.example .env
code .env
Set-ExecutionPolicy -Scope Process Bypass

.\scripts\database\Start-DatabaseStack.ps1
.\scripts\database\Initialize-Database.ps1 -InstallDependencies -SeedDemonstrationData
python -m alembic upgrade head
python -m pytest -q

cd apps\web
npm ci
npm run typecheck
npm run build
npm run dev
```

## Required live scenarios

1. Lecturer selects an assigned IoT module and generates a two-hour practical lesson.
2. Lecturer edits the output twice and restores version 1; four immutable versions should exist.
3. Lecturer generates a test; the result is marked for review and cannot be directly released.
4. Head of Department or coordinator reviews, requests changes, approves and releases within authorised scope.
5. Institution Administrator cannot approve merely because of the admin role.
6. External moderator can review only the assigned assessment.
7. Export Word, PDF, PowerPoint and Excel lecturer packs.
8. Export a student copy and verify that answer/memorandum sections are absent.
9. Attempt cross-tenant output, version, export and module-context access; all must fail.
10. Revoke the session and confirm immediate access denial.

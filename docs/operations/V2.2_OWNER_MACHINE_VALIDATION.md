# v2.2 Owner-Machine Validation

## Prerequisites

Use the cumulative v2.2 project outside OneDrive. Keep real credentials only in the ignored `.env` file. Start Docker Desktop manually and confirm Ollama is running.

## 1. Repository and dependency validation

```powershell
Set-ExecutionPolicy -Scope Process Bypass
python .\scripts\validation\validate_v22_release.py
python -m pytest -q
npm --prefix .\apps\web run typecheck
```

## 2. Start infrastructure and migrate

```powershell
.\scripts\database\Start-DatabaseStack.ps1
.\scripts\database\Run-Migrations.ps1
.\scripts\database\Seed-DemonstrationData.ps1
```

Verify that migration `20260726_0008` creates the `analytics` schema and eight v2.2 tables.

## 3. Tenant and role security

Run the existing tenant-isolation tests and verify:

- a lecturer cannot request institution scope;
- a Head of Department cannot request institution scope or use Audit Centre;
- an external reviewer sees only personal insight data;
- an Institution Administrator can read institution analytics and Audit Centre;
- tenant A cannot read tenant B analytics, settings, policies, reports or audit exports.

## 4. AI governance

1. Confirm Ollama models with `ollama list`.
2. Create a local-only policy for `restricted_assessment`.
3. Submit a restricted assessment request and confirm only Ollama is attempted.
4. Disable Ollama and confirm the request fails closed.
5. Configure a source-required task and confirm verified-source handling is invoked.
6. Confirm the daily ledger records user, provider, model, task, tokens, latency and status.
7. Test an advisory threshold and a hard limit.

## 5. Reports and Audit Centre

- Generate each seeded report type for the authorised scope.
- Confirm repeat runs preserve separate immutable records and distinct timestamps.
- Verify the result SHA-256 against the canonical payload.
- Search audit events by actor, action and date.
- Generate JSON and CSV audit exports and verify digest and record count.
- Confirm non-administrators receive HTTP 403.

## 6. Platform settings

- Update terminology and analytics-default settings.
- Confirm version increments and audit events.
- Attempt to store an API key and confirm rejection.
- Store only an environment-variable reference for a secret-backed setting.

## 7. Live application validation

Run the API and Next.js frontend, then validate all roles at desktop, tablet and mobile widths. Capture evidence for Insights, Reports, Audit Centre and Settings, including loading, empty, error and populated states.

## 8. Consolidated evidence

Run:

```powershell
.\scripts\validation\Invoke-ConsolidatedOwnerValidation.ps1 `
  -Mode full `
  -InstallDependencies `
  -StartInfrastructure `
  -RunLivePreview
```

Owner-machine acceptance requires the final evidence report to show `validated_on_owner_machine`. Until then, runtime validation remains pending.

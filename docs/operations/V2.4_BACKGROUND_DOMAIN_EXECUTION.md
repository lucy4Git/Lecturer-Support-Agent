# v2.4 Background Domain Execution

## Worker cycle

1. Recover expired leases through a restricted database function.
2. Materialise due interval schedules through `operations.enqueue_due_scheduled_jobs`.
3. Claim one job under the `lsa_worker` database role.
4. Set the tenant context for row-level security.
5. Execute the registered handler.
6. Commit a completed result or a bounded retry/dead-letter record.

## Connected handlers

| Job type | Behaviour |
|---|---|
| `notifications.dispatch` | Records real in-app delivery; other channels are visibly blocked until configured. |
| `outbox.publish` | Marks events published to the internal durable database stream. |
| `external_access.expire` | Expires due grants and records expiry evidence. |
| `governance.apply_retention` | Previews or applies reversible retention actions. |
| `analytics.generate_report` | Completes an existing report run and stores a digest. |
| `audit.generate_export` | Produces JSON or CSV audit evidence and a digest. |
| `content.ingest_document` | Uses object storage, parsers, Ollama embeddings and Qdrant. |
| `content.generate_export` | Renders an immutable output version and stores it in versioned object storage. |

Backup and restore-drill handlers remain owner-machine integration gates.

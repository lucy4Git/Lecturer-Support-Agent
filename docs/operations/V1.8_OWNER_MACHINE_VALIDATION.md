# v1.8 Owner-Machine Validation

Run this checkpoint after extracting the cumulative v1.8 package and before a Claude implementation audit.

## 1. Preserve secrets

```powershell
Copy-Item .env.example .env -ErrorAction SilentlyContinue
# Add real values locally only. Never upload .env.
git check-ignore -v .env
```

## 2. Start infrastructure manually

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\database\Start-DatabaseStack.ps1
.\scripts\database\Run-Migrations.ps1
```

Docker Desktop is not launched automatically.

## 3. Run cumulative validation

```powershell
python -m pytest tests\unit -v
python .\scripts\validation\validate_v18_release.py
node .\scripts\validation\Validate-TypeScriptSyntax.js
```

## 4. Validate review security with seeded accounts

Test at least these separate sessions:

- Lecturer who owns the output;
- Head of Department;
- Module or Programme Coordinator;
- Internal Moderator assigned to the output;
- Internal Moderator not assigned to the output;
- External Moderator with valid grant;
- External Moderator with wrong resource scope;
- External Reviewer with expired grant;
- Institution Administrator without academic decision authority;
- User from another institution.

Prove that the assigned reviewer can access only the sealed version and that all negative cases return an appropriate denial without revealing the resource.

## 5. Correction-round workflow

1. Generate a test assessment.
2. Submit it for review.
3. Create an internal moderation cycle.
4. Accept and start the assigned task.
5. Record one blocking and one non-blocking finding.
6. Submit a `changes_required` recommendation.
7. Record the authorised decision.
8. Create a new output version and respond to findings.
9. Resubmit corrections.
10. Verify that a new pack and task round were created and the old round did not change.
11. Approve, release and export the permitted copy.

## 6. Browser and responsive validation

Run the Next.js application and confirm the inline **Create review cycle**, **Review tasks**, and **Review oversight** controls on desktop, tablet and mobile widths. Validate keyboard navigation and readable focus states.

## 7. Evidence

Store command logs, screenshots, migration output, failing/denied access cases and test results under a local validation evidence folder. Do not include secrets or confidential assessments in the shared ZIP.

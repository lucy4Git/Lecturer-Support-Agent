# v1.6 Document ingestion and authorised retrieval

## Pipeline

1. Authorise the active role for the selected institutional scope.
2. Inspect files and safe ZIP members; reject traversal, symbolic links, encryption, nested archives, and size-limit breaches.
3. Store every changed file as a new object and logical document version.
4. Extract text from supported files without OCR fabrication.
5. Mark media as transcript-required and images as preserved-but-unindexed until an approved image extraction strategy exists.
6. Chunk extracted text deterministically and create governed embeddings.
7. Index only the specific version in Qdrant with tenant, owner, scope, visibility, current-version, and provenance payloads.
8. Re-authorise every retrieval result through PostgreSQL before prompt use.
9. Persist retrieval traces, source records, citations, and audit evidence.

## Supported v1.6 extractors

Plain text, Markdown, CSV, JSON, HTML, PDF text, DOCX, PPTX, XLSX, SRT, and VTT. Audio/video require transcripts. Image OCR is deliberately disabled rather than producing uncertain text.

## Version behaviour

An exact binary duplicate links to the existing version. A changed file creates a new version and never deletes prior object versions or provenance. Default semantic retrieval selects current versions only; historic versions remain available through authorised version history.


## Controlled lifecycle

Each logical file version has an explicit status. The supported transition graph prevents silent publication or approval and writes every change to `content.document_version_transitions` with the actor, active role, reason, scope and timestamp. An archived version cannot be reopened by an implicit overwrite; a new version must be created when work resumes.

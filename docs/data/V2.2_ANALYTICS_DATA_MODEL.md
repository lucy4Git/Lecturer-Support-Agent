# v2.2 Analytics Data Model

## Schemas

- `analytics`: operational snapshots, daily AI usage, report definitions, report runs and insight alerts.
- `governance`: AI usage policies and versioned platform settings.
- `audit`: checksum-protected audit export jobs in addition to the existing event records.

## Table summary

### `analytics.ai_usage_daily`

A daily, tenant-owned ledger keyed by date, user, provider, model, role and task. It records request outcomes, input/output tokens, estimated cost, currency and accumulated latency.

### `analytics.analytics_snapshots`

An immutable snapshot of a resolved insight view. It retains period, scope, metrics, data watermark, generator and timestamp.

### `analytics.report_definitions`

Reusable governed report templates with type, default scope, parameters, formats, owner and sharing state.

### `analytics.report_runs`

A requested report instance with exact scope, parameters, format, immutable result payload, result digest, status and error information.

### `analytics.insight_alerts`

Actionable operational or governance findings with category, severity, metric, threshold, scope, action path and acknowledgement/resolution history.

### `governance.ai_usage_policies`

Provider, privacy, source and monthly-limit rules. The policy does not store provider credentials.

### `governance.platform_settings`

Versioned, non-secret settings by tenant, category, key and optional scope. Secret-backed values contain references only.

### `audit.audit_export_jobs`

A checksum-protected audit export request with filters, format, count, payload or future storage reference, status and error details.

## Retention guidance

- Daily AI usage: retain according to institutional financial and audit requirements.
- Snapshots and report runs: retain while they support operational decisions, evaluation or compliance evidence.
- Audit exports: use a short download retention period while preserving the source audit events under the audit policy.
- Settings and policies: preserve version and audit history; do not destructively overwrite governance evidence.

## Multi-tenancy

All eight tables carry `tenant_id`. RLS and service-level scope checks are both required. Qdrant and object-storage records are not introduced by this phase, but any later rendered report object must also carry tenant and report-run identifiers.
